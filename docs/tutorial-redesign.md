# チュートリアル改善案の検討（2026-08-15）

コードと突き合わせた検証結果。実装前の設計メモであって、まだ何も実装していない。

## 1. ユーザー案の評価

### 良い点

3つある。いずれも現行より明確に優れており、推奨案でもそのまま残した。

第一に、単語と単語リストへ重点を置く判断。現行は8ステップ中5つが「ボトムナビを左から右へなぞる」だけのタブ巡回で（`components/english/TutorialFlow.tsx:34-51` の switch が 2:vocab / 3:database / 4:grammar / 5:reading / 6:chat と `EnglishApp.tsx:47-53` の TABS 定義順に完全一致）、アプリのコンセプト4本柱が全部単語カードと復習の話であることと配分が合っていない。

第二に、「知っている→○、知らない→×」という意味づけを先に置く判断。現行のデモはジェスチャ（右・左・上）は教えるが、なぜ仕分けるのかを一言も言わない。記号の意味はボタンの `aria-label` にも書かれておらず（`components/english/VocabTab.tsx:1057-1058` は `title="△"` / `aria-label="△"` と記号のみ）、画面のどこにも存在しない。ここは実在する欠落で、案が正しく突いている。

第三に、①→②→③の因果の線。測定直後は `PLACEMENT_SIZE = 10`（`lib/english/worddb.ts:425`）ちょうどの語が `record()` で1問ずつ記録されるため（`VocabTab.tsx:1296-1298`）、単語リストに自分が直前に答えた10語だけが並ぶ。抽象説明ではなく自分のデータで確認できる状態で、教材として最良。現行の step3 はこれを実現できておらず、測定を飛ばすと0行になる。

④の文法・読解・AI会話を「こんな機能もあります」に格下げする判断も妥当。現行は3ステップと3回のタブ移動を消費し、読解の tryIt は「長文を生成で試せます (数十秒かかります)」（`TutorialFlow.tsx:440`）と初回ユーザーに数十秒の待機を要求している。

### 事実として直すべき点

以下はコードと食い違っている。

**「演習モードで実際に10単語振り分け（ここでユーザーの単語力を測定）」は成立しない。** 測定(placement)と演習(drill)は別物として実装されている。phase が別（`VocabTab.tsx:70-76` の Phase 型、測定は `:1282` の `startPlacement`、演習は `:1890` の `phase === "quiz"`）、ハンドラが別（`onPlacementAction` `:1296` / `onPlacementNext` `:1306` に対し、演習は `:1941` 付近の `record(item, a, mode === "drill" && kind === "words")`）、記録の扱いも別（測定は `record(pItem, action, false)` で直近正解率に加算しない、`:1298`）。演習の回答が測定を起動する経路は存在せず、逆に未測定のうちは `VocabTab.tsx:1717-1744` のゲートが他のどの分岐より先に return するので演習画面に到達できない。順序は必ず測定→演習で固定されている。

**「①は○と×の2択、△は③で初めて説明」は画面と食い違う。** 測定画面はモードの設定を無視して △ と解説を強制する（`VocabTab.tsx:1786-1789` に「測定は正確さが要るので、モードの設定によらず ? を出して解説も見せる」というコメント付きで `showUnsure` と `skipReveal={false}` を渡している）。①でユーザーが見るボタンは × △ ○ の3つになる。

**「スワイプ設定」は旧称。** 画面の見出しは「単語の設定」（`components/english/CardFilterSheet.tsx:155`）。旧称は `VocabTab.tsx:1610` の `aria-label` と本文3か所（`:1703` `:1985` `:2043`）、`TutorialFlow.tsx:357` に残っているだけ。

**「学習完了までの連続○回数」という設定項目名は存在しない。** 実際は「単語の設定」→「出題カードのフィルタリング」→「復習モードの出題設定」の中の行ラベル「学習完了とみなす回数」（`CardFilterSheet.tsx:322` が見出し、`:361` がラベル、入力は min=1 max=10）。

**「○を3回連続で学習完了」は既定値かつ限定条件でのみ正しい。** 3 は `masterKnownCount` の既定値にすぎず1〜10に変更可（`lib/english/types.ts:317`）。さらに `progressOf`（`lib/english/worddb.ts:142-160`）の判定順に抜け道がある。`:157` の `if (entry.history[0].r === "known") return "done";` が `:158` の連続回数判定より先にあるため、初見が○だった語は、その後×を何回出しても○を1回取るだけで学習完了に戻る。未学習の語も「学習中」を経由せず1回の○で完了へ直行する（`:146` → `:157`）。案の状態遷移は全経路を説明していない。

**「初回で知らなかった単語は学習中」は二分法として不正確。** ①で△が出る以上、実際は○ / × / △ の3通りが起こる。△は4択に正解した `unsure_correct` でも学習中になる（`worddb.ts:156` で直近が known 以外なら learning）。

**「×が多い単語ほど多く出題」は方向は合っているが前提が抜けている。** 重みの式は `worddb.ts:198-209` で正しいが、抽選の前に学習進捗度で母集団が切られる（`worddb.ts:383-389`、既定の `reviewProgress` は `["learning"]`、`types.ts:320`）。学習完了と判定された語は×を何回持っていても復習に出ない。`:157` の近道と組み合わさると「×が多いのに永久に出ない語」が生じる。

**「設定へページ遷移して認知をとる」は現状の実装では実行できない。** 4点。(1) 開閉 state は `VocabTab` のローカル（`VocabTab.tsx:1129` の `useState(false)`）で、Props は `data` と `setData` の2つだけ（`:65-68`）。外から開く口が無い。(2) `filterSheet` を描画しているのは `:1712`（イディオム＋未測定）と `:1895`（quiz）の2か所だけで、①の時点で通る未測定ゲート（`:1717-1744`）・測定中（`:1746`）・測定結果（`:1794`）のどこにも無い。open にしても何も出ない。(3) `Collapsible` は非制御で `open` は内部 `useState(defaultOpen)`（`components/english/Collapsible.tsx:25`）、目的のセクションだけ開いた状態で出せない。しかも「スワイプ時オプション」は `defaultOpen` が付いておらず既定で閉じている（`CardFilterSheet.tsx:384-387`）ので、「回答する前に見せる項目」（`:410`）はシートを開いただけでは見えない。(4) Sheet の背面が `fixed inset-0 z-[45]`（`components/english/Sheet.tsx:85-91`）で全画面を覆うのに対し、`TutorialBanner` は z 指定なしの通常フロー（`TutorialFlow.tsx:454`）。シートが開いている間は「次へ」が押せず、押しても背面に当たってシートが閉じるだけになる。

**「前回結果」列と「○△×」列を指し示す仕組みが無い。** `components/english` 配下に `id` / `data-testid` / `data-tour` / `scrollIntoView` は0件。表は `min-w-[820px]` の横スクロール枠に入っており（`components/english/WordListView.tsx:698`）、枠への ref も `scrollLeft` 制御も無い。加えて○△×の3列は累計回数で前回結果はバッジという違いは `th` の `title` 属性にしか書かれておらず（`WordListView.tsx:705-707`）、タッチ端末では原理的に表示されない。

**シール演習は操作も検知もできない。** `sealed` / `peeled` は `WordListView` 内部の useState（`:165-172`）で Props は data/setData のみ（`:133`）。タブを移ると `WordListView` はアンマウントされて全消去（`EnglishApp.tsx:427`）。

**②の「演習した単語が表示される」は条件が違う。** 表示条件は `data.vocab` に回答記録があること。既定フィルタが `["learning","done"]`（`WordListView.tsx:60`）で未学習が落ちるだけなので、測定・復習・カード詳細からの回答もすべて含まれる。

**③の「1単語復習させる」は全問○のとき成立しない。** 復習プールは learning の語だけ（`worddb.ts:383-389`）。測定10問すべて○だと0件になり「復習する単語はありません」の空画面に落ちる（`VocabTab.tsx:1978-1985`）。また測定結果画面の「学習をはじめる」は `setPhase("quiz")` だけで mode は drill 固定（`VocabTab.tsx:1808-1813`）なので、復習へ入れる導線が今は無い。

## 2. 構造上の懸念

**チュートリアル自身が、自分の出した唯一の課題を壊す。** `onNext` は無条件に `goTourStep(step + 1)` を呼ぶだけで測定の進行を一切見ていない（`EnglishApp.tsx:108`）。次のステップへ進むと `goTourStep` が `setTab()` を実行し（`:97-98`）、`{tab === "vocab" && <VocabTab .../>}`（`:426`）で VocabTab がアンマウントされる。測定の進行状態 `pLadder` / `pTrack` / `pSeen` / `pItem` / `pCount` は VocabTab のローカル useState（`VocabTab.tsx:1151-1156`）なので丸ごと消える。しかも回答は `record()` で `data.vocab` に書き込み済みなので、記録だけ残って `vocabLevel.current` は null という中途半端な状態になる。さらに `lib/english/storage.ts:438-443` の `normalize` が `Object.keys(vocab).length > 0` で `tutorialDone` を true と推測するため、測定に1問答えて閉じたユーザーは次回起動でチュートリアルが二度と自動再開しない。最も混乱している人が案内を永久に失う。`docs/english-app.md:702` と `:787` に既知課題として登録済みで、ユーザー案は測定・演習・復習と3回手を動かさせる設計なので、これを直さないと同じ罠を3回踏む。

**説明文が目の前に無い画面を指している。これが「わかりにくい」の一次的な発生源で、説明量の問題ではない。** 現行のユーザー向けコピーは全部で900字弱しかなく、量として過大ではない。実害は不一致のほう。(a) 未測定ユーザーの step2 バナーは「下の10問に、さっき覚えたスワイプでそのまま答えてください」（`TutorialFlow.tsx:421`）と言うが、画面に出ているのは「まず単語レベルを測定します」と「測定をはじめる (10問)」ボタン1個だけ（`VocabTab.tsx:1717-1744`）。下に10問は無く、そのボタンを押せという指示もどこにも無い。初回ユーザーが最初に出会う指示が実行不可能な指示になっている。(b) 10問完走した瞬間、`measured` が毎レンダー再計算される（`EnglishApp.tsx:107`）ためバナー本文が予告なく差し替わり、「左上がスワイプ設定」と書かれる（`TutorialFlow.tsx:420`）が、そのときの画面は結果画面（`VocabTab.tsx:1794-1816`）で modeTabs も設定ボタンも存在しない。(c) step3 のバナーは「見出しの目のアイコンで」（`:427`）と案内するが、記録が0件だと `<table>` ごと描かれず「該当なし」の1行になる（`WordListView.tsx:695-698`）ので、指している見出し行が DOM に無い。読み手は自分の理解力を疑うが、実際には文章が画面を指していない。ユーザー案は説明を増やす方向だが、増やしても不一致は直らない。

**バナーが説明の帯であると同時に、答えるボタンを画面外へ追い出している。** `TutorialBanner` はオーバーレイではなく唯一のスクロールコンテナの先頭に通常フローで置かれる（`EnglishApp.tsx:417-425`、`TutorialFlow.tsx:454` の `mb-4 rounded-2xl border-2`）。一方 VocabTab の quiz / placement 分岐のルートは `flex h-full flex-col`（`VocabTab.tsx:1746` `:1893`）で、`h-full` はコンテナ高さの100%を意味するため、バナーの高さぶんだけ下端が確実にはみ出す。はみ出す下端にあるのが ×△○ の回答ボタン列。`docs/english-app.md:819` に既知課題として登録済み。つまり「実際に答えてみましょう」と書いてある帯そのものが、答えるボタンを追い出している。ユーザー案は①だけで4項目、②で5項目と説明を厚くする方向なので、同じ書き方を続けると悪化する。しかも「戻る」「次へ」「スキップ」はバナーの中にしか無いので、指示どおり中身を触ろうとスクロールした瞬間に進む手段も画面外へ出る。

**アプリの中核概念である演習と復習の違いが、初回ユーザーには構造上一度も表示されない。** これを説明している文字列はアプリ全体で1か所しかなく、それが `measured ? A : B` の A 側（測定済み向け、`TutorialFlow.tsx:418-421`）にある。初回ユーザーは step2 で必ず `measured === false` なので B 側を読み、A 側を読む機会が無い。画面側でも救われず、`modeTabs`（演習 / 復習のタブ）を描画するのは quiz 分岐（`VocabTab.tsx:1897`）とイディオム未測定分岐（`:1695`）の2つだけで、初回チュートリアルで通る未測定ゲート・測定中・結果画面の3画面にはいずれも無い。現行のチュートリアルを最後まで通しても「演習」「復習」という語が画面に一度も現れずに終わりうる。ユーザー案が①演習・③復習を柱に据えたのは、この穴を正しく突いている。

**8ステップ中7つに達成条件が無く、唯一の例外は逆に操作を奪って勝手に進む。** 進行を止める条件分岐はコードのどこにも無く、10問に答えなくても文法を1問も解かなくても「次へ」で素通りできる。各バナーの `▶ {tryIt}`（`TutorialFlow.tsx:470-472`）は任意のお願いで、達成の検知も表示も無い。「やれと言われたが誰も見ていないし、やらなくても進む」という学習が最初の数ステップで成立し、以後の文章は読まれなくなる。唯一達成条件を持つ step1 は逆方向に振り切れていて、3ゴール達成の1100ms後に `setTimeout` で `onNext` が呼ばれる（`TutorialFlow.tsx:165-171`）。8つのうち7つは「押さないと進まない」、1つだけ「押せないうちに勝手に進む」。これは説明量の問題ではなく契約の不在の問題で、説明を減らしても増やしても直らない。

## 3. 推奨案

全5ステップ。順序は 測定 → 単語リスト → 演習 → 完了。ユーザー案の①→②→③をコード上通れる順に組み替えたもの。単語リストを演習より前に置くのは、測定直後だけ「さっき答えた10語ちょうど」という最良の状態になるため。演習を最後に置くのは、チュートリアルを閉じた瞬間ユーザーが既に毎日使う画面にいる状態を作るため。

タブ移動は3回（vocab → database → vocab）。現行の5回から減る。

### step 0　全画面オーバーレイ「カードの答え方」

画面に出るもの: 見出しとサブ、本物の `WordCard` を使ったデモ（`DEMO_ITEMS` の4語を modulo で回す、記録系コールバックは全て noop、飛んでいくコピーも現行のまま）、ゴール2行（達成でチェック）、補足1行、下部にドットとボタンとスキップ。

ユーザーの操作: カードを右へ1回、左へ1回スワイプする（下のボタンでも可）。

次へ進む条件: ゴール2つ達成。達成するまで下のボタンは無効。1.1秒の自動進行は廃止し、必ずユーザーがボタンを押す。

バナー文言:

```
カードの答え方

知っている単語と知らない単語を仕分けて、知らない単語だけを
繰り返すアプリです。

→  右へスワイプ = ○ 知っている
←  左へスワイプ = × 知らない

迷ったときは真ん中の △。意味の4択が出ます。
下のボタンでも答えられます。ここでの回答は記録に残りません。

[ボタン] 未達成: 「まず2つ試してください」（無効）
         達成後: 「レベル測定へ」
```

現行 step0 の3枚の Row（スワイプで覚える単語カード / レベルは自動調整 / 文法・読解・AI会話）は削除し、3枚目の内容は step4 へ移す。起動0秒目の機能紹介は読まれない。

### step 1　バナー（単語タブ）「レベル測定 (10問)」

画面に出るもの: 未測定なので `VocabTab` は測定導入画面（「まず単語レベルを測定します」と「測定をはじめる (10問)」ボタン）を返す。押すと測定カードが10問続き、10問目の直後に結果画面（「あなたの単語レベル B1」）になる。

ユーザーの操作: ボタンを押して10問に答える。

次へ進む条件: `data.vocabLevel.current !== null`（10問完走）。満たすまで「次へ」を無効化し、「戻る」も無効にする。測定中に画面を移動させないための唯一のゲート。

バナー文言（未測定）:

```
チュートリアル 2 / 5                          スキップ
レベル測定 (10問)
下の「測定をはじめる」を押して、10問に答えてください。答え方は
さっきと同じ、○ と × と △ の3つです。正解すると難しい単語、
間違えると易しい単語が出て、レベル (A1〜C1) を判定します。
[戻る（無効）]  [10問終えると進めます（無効）]
```

バナー文言（10問完走、結果画面が出た瞬間）:

```
レベル測定 (10問)
測定できました。いま答えた10語がどう仕分けられたか、次の画面で
見てみましょう。
[戻る]  [答えた10語を見る]
```

既存の `measured` 分岐（`EnglishApp.tsx:107`）の器はそのまま使い、割り当てを正しい向きに直す。

### step 2　バナー（単語リストタブ）「単語リスト」

画面に出るもの: 測定で答えた10語がちょうど10行。既定フィルタが学習中と学習完了なので、記録のある語だけが並ぶ。既定の並び順で × から ○ へ並ぶ。

ユーザーの操作: 表を見る。任意で見出しの目のアイコンを押す。

次へ進む条件: なし。step1 のゲートにより、このステップに来た時点で必ず10行あることが保証されている。

バナー文言:

```
チュートリアル 3 / 5                          スキップ
単語リスト
さっき答えた10語です。「学習進捗度」の列を見てください。○ だった
語は「学習完了」、× と △ だった語は「学習中」です。復習に出るのは、
この学習中の語だけです。
▶ 見出しの目のアイコンを押すと、単語や意味を隠して覚えられます
[戻る]  [単語に戻る]
```

扱う軸は学習進捗度の1つだけに絞る。行動に効くのはこの1軸だけで、復習の母集団を決めるのもここ。前回結果列と○△×の回数列は、同じ記号で意味が違うのに説明が `title` 属性にしかないので、初回では触れない。

ユーザーの操作: カードを1語仕分ける。

次へ進む条件: このステップに入ってから回答が1件増えたこと。

バナー文言（未回答）:

```
チュートリアル 4 / 5                          スキップ
演習
ここが毎日使う画面です。演習は ○ と × の2つだけで仕分けます。
迷ったときの △ は復習で使います。
▶ カードを1枚仕分けてみましょう
```

**1. step1 に測定10問のゲートを入れるか。**　選択肢は (a) 入れる。10問完走まで「次へ」と「戻る」を無効化する。(b) 入れず、測定中は警告を出すだけにする。推奨は (a)。これが今回いちばん効く変更で、チュートリアル自身が測定を壊す導線（`docs:702`）が構造的に消え、後続の単語リストが必ず10行ある状態になる。代償は、逃げ道が「スキップ」だけになること。単語DBの読み込みに失敗した場合も「次へ」が押せずスキップ一択になる点を許容するかは確認したい。
