# 英語学習アプリ 引き継ぎメモ

新しいセッションでこのアプリの開発を続けるときは、まずこのファイルを読む。

## 1. コンセプト（すべての設計判断の基軸）

前提: モバイル版での使用を前提に作る。デスクトップは二の次。

1. 単語カードのスワイプと編集。スワイプはページをめくる感覚、編集は絵やメモを書き込む感覚。
2. シンプルすぎるUI/UX × 高度なカスタム機能。表に出す要素は極限まで減らし、ソート・フィルタ・表示項目は深くいじれるようにする。
3. 一人一人の学習方法に合ったカード作成と、スワイプ時の表示/非表示設定。
4. 間違えた回数に応じた重み付け復習。×・△ が多い語ほど復習によく出る（× を特に重く）。
   ※ もともとは「エビングハウスの忘却曲線」だったが、期限方式は実装後にユーザーの判断で撤回した（6章参照）。

## 2. 起動と確認

開発サーバーは `.claude/launch.json` の `english-app`（ポート3200）を preview_start で起動する。Bashで `npm run dev` は使わない。

```bash
npx tsc --noEmit
```

```bash
npx eslint components lib app
```

画面は http://localhost:3200/english （ルート `/` もそこへリダイレクトする）。確認は必ずモバイル幅（375×812, resize_window の mobile プリセット）で行う。ページ全体が横スクロールしたらレイアウト崩れとみなす（単語一覧テーブルの内部横スクロールは正常）。

eslint は**既存分として 7 errors / 2 warnings（計9件）が残っている**。これは以前からのもので、自分の変更で件数が増えていなければよい。件数を基準に見ること。

状態は localStorage の `english-app-data-v1` に入っている。ブラウザのJSから読むとテストしやすい。検証でユーザーの学習記録を書き換えたら、必ず元に戻してから終わること。

`window.confirm` はこの環境では何も表示せず false を返す。確認ダイアログの動作確認は `ConfirmButton`（画面内の二段階確認）で行う。

## 3. 技術スタック / 決まりごと

- Next.js 16.2.4（App Router, Turbopack）, React 19.2.4, TypeScript, Tailwind v4。
- リポジトリ直下の `AGENTS.md` に従い、Next.js のコードを書く前に `node_modules/next/dist/docs/` の該当ガイドを読む。訓練データの知識と食い違う箇所がある。
- Anthropic SDK は `max_tokens` が大きいとき（8k超）`client.messages.stream().finalMessage()` を使う。非ストリームだと拒否される。構造化出力は `output_config: { format: { type: "json_schema", schema } }`。
- APIの残高切れは `BadRequestError` (400) で来る。`handleGenerateError` で専用の文言に振り分けてある。生成系が急に全部失敗したらまず残高を疑う。
- モデルIDは `claude-opus-5`。
- 配色はX（Twitter）準拠。黒・白が基本、アクセントは `#4A99EA`、エラー・危険は赤、△の黄のみ例外的に使う。カードの○は青枠、△は黄枠、×は赤枠。ボタンはピル型、区切りは細線。
- このアプリは端末の設定によらず常にダークテーマ。新しく書く要素も「暗い地に明るい文字」を既定にする（詳細は5章）。
- 日本語UIの句読点は「。、」。

## 5. 設計上の決定と、その理由

- ユーザーの編集は `EnglishData.edits` にオーバーライドとして保存し、DBファイル自体は書き換えない。DBを再生成しても編集が消えないため。
- 単語・文法はAPIを呼ばない。生成待ちが体験を壊すので、事前生成DBから即出題する。
- レベルはユーザーが選ぶのではなく最初の10問で測り、以後は正答率で動的に上下させる。苦手タブの出題語も現在レベルに追随する。
- 測定の10問目に答えた時点で、測ったレベルの最初のキューまで作ってしまう（`onPlacementNext`）。結果画面の「学習をはじめる」は `phase` を `quiz` にするだけ。
  - 以前はここで `idle` に落としていたが、`idle` の画面は「出題できる単語がありません。設定を見直すか、レベルを再測定してください」しか出さないので、測定を終えた直後に行き止まりに突き当たっていた。測定とキュー作成のあいだに `setData` の反映待ちを挟まないよう、レベルは state ではなく測定値 `est` から直接渡す。
  - 測定に使った10語は `pSeen` として除外して積む。測ったばかりの単語がそのまま続けて出ると測定の続きに見えるため。
- `idle` の画面は「出題対象レベルが1つも無い」ときと「レベルはあるが出題できる語が無い」ときで文言とボタンを分ける。前者では `switchMode` がキューを作れず「出題する」ボタンが無反応になるので、測定への導線を出す。
- カード画面の上部タブは出題モードそのもの。**演習**と**復習**の2つだけ。
  - 演習 … 高速に ○ / × へ仕分ける。ボタンは × ○ の2つ、既定では回答後に裏面を見せない。出題は「新出（未学習）」と「既出（学習中＋学習完了）」を `drillNewRatio`（既定50%）で混ぜる。片方の在庫が尽きたらもう片方で埋めるので、比率はあくまで目安。
  - 復習 … 取りこぼした語を覚え直す。ボタンは × △ ○ の3つ、既定では裏面を見せる。出題は**学習進捗度が学習中**のものだけ。
  - タブの件数は `buildQueue` が同じモードで拾う集合と一致させる（復習の件数 = `dbStats().learning`）。片方だけ直すとズレる。演習は無限に出し続けるので件数を出さない。
  - 更新（↺）とコメント（💬）のボタンは削除した。メモはカード右下の ↑ から詳細を開いて書く。
  - 「解説を飛ばす」は ○ / × だけでなく **△（4択）にも効く**。選択肢を押した時点で正誤も見せずに上へ飛ばす。片方だけ飛ばすと、設定を入れているのに △ で毎回止まる。
- レベルの自動調整（`evaluateLevelShift`）は演習モードの回答だけで判定する。復習は苦手な語に偏るので、数えるとレベルが不当に下がる。
- 出題対象レベルは1つとは限らない。`activeLevels()` が自動設定なら測定値の1つ、手動設定なら選択したぶんすべてを返し、`buildQueue`/`dbStats` は `Level[]` を受け取る。手動設定のあいだは正答率によるレベル自動調整（`evaluateLevelShift`）を走らせない。
- ステータスは**2軸**で持つ。1つに混ぜると「なぜこの語が出るのか」が読めなくなるため分けてある。
  - 前回結果（`LastResult`）… 最後にユーザーが答えた結果そのもの。○ / △ / ×。未回答なら `null` でバッジを描かない。○ を付ければ ○、あとで × を付ければ × に変わるだけで、それ以外の意味は持たせない。
  - 学習進捗度（`Progress`）… 未学習 / 学習中 / 学習完了。**出題の対象はこちらで決める**。
- 学習進捗度の判定は `progressOf()` の1か所だけ。未出題なら未学習、**初見で ○ を出した語**または ○ が `masterKnownCount` 回（既定3）連続した語が学習完了、残りが学習中。
  - **どちらも「前回結果が ○」であることが条件。** あとで △ や × を出したら学習中へ戻る。この条件が無いと、一度学習完了になった語は忘れても永久に学習完了のままで、学習中だけを拾う復習モードに二度と出てこなくなる（実データで12語が該当していた）。
  - 初見の判定に **△→正解 は含めない**。「怪しいが4択は当たった」は身についたとは言えない。以前 `isCorrect(history[0])` にしていたため、前回結果が × なのに学習完了という組み合わせが生まれていた。
  - 連続は `consecutiveKnown()`。△ や × を挟むと数え直す。累計だと一度覚えた語が誤答を挟んでも完了のままになる。
- 色は軸ごとに系統を分ける。前回結果は ○=青（`#4A99EA`）/ △=黄（`yellow-500`）/ ×=赤。学習進捗度は 未学習=白 / 学習中=灰 / 学習完了=黒。

- 「学習済みなら出題しない」「初見の○は永久に出さない」「n日で再出現させる」の3つは廃止した（`masterKnownCount` は学習完了の判定にだけ残っている）。裏で分類が変わると自分の回答と表示が食い違い、なぜその語が出るのか分からなくなるため。

  - 重みは `1 + ×回数×3 + △→誤答×2 + △→正解×1`、さらに直近の結果を上乗せ（前回 × なら +4、前回 △ なら +2）。× を特に重く、というユーザーの指定。
  - 4択で当てた回数（`correctCount`）も加点する。「怪しい」と自己申告した証拠だから。
  - 復習の対象は今までどおり**学習進捗度が学習中のものだけ**。件数も `stats.learning` のまま。
  - 数字を変えたら `scripts/check-english-queue.ts` の検算も合わせて直す（重みの単調性と、×多い語が実際に先に出る割合を大数で確かめている）。
- 読み上げはブラウザ内蔵の Web Speech API だけで作る。追加のキーも費用も要らず、認証の無い公開URLを他人に使われても請求が増えないため（**Anthropic API には音声が無い**ので、クラウドTTSを使うなら別プロバイダの契約が要る）。差し替えるときは `lib/english/speech.ts` の中だけを直す。
  - iOS Safari の罠が2つある。**最初の `speak` はユーザー操作の中から呼ばないと無音になる**ので、カードに触れた時点で `primeSpeech()`（音量0の空発話）を1回通して解錠する。`getVoices()` は非同期で初回だけ空配列を返すので `voiceschanged` を待って選び直す。声が選べていなくても `lang` は必ず英語にする（指定しないと端末の既定言語で読まれ、英単語がローマ字読みになる）。

  - **速さは `speech.ts` のモジュール変数が1つ持ち、`EnglishApp` から `setSpeechRate()` で同期する。** 読み上げを持つ画面が4つ（カード・カード詳細・単語リスト・長文）あり、prop で配ると渡し忘れた画面だけ既定に戻る。
  - **`primeSpeech()` は `answer()` と `openChoices()` の中でも呼ぶ。** 下部の × △ ○ ボタンはカード本体の外にある兄弟要素なので、ボタンだけで仕分けているとカードの `onPointerDown` を一度も通らない。演習は「× ○ の2ボタンで高速に仕分ける」のが本来の使い方なので、これが例外ではなく主経路。カードに触れない限り解錠されず、iOS では自動読み上げが永久に無音になる。
  - `speak()` は必ず前の発話を `cancel()` してから始める。止めないとカードを続けてめくったとき読み上げが順番待ちで溜まる。
  - **飛んでいくコピー（ghost）では読み上げない。** 本体で既に読んでいるので二重になる（振動と同じ扱い）。コピーの unmount で `stopSpeaking()` を呼ぶのも禁止。コピーは飛び終えた直後 (EXIT_MS+80ms) に片付くので、その頃には手前に出ている次のカードの読み上げを切ってしまう。

- 発音記号はユーザーが編集できない。全7,634件に付与済みで、手で直す必要がないため。

- このアプリは端末がライトモードでも常にダークにする。実装は `app/globals.css` の `@custom-variant dark` で、`dark:` が当たる条件を「端末がダーク **または** `.dark` を付けた要素の中」の2本立てに広げ、`app/english/page.tsx` の `main` に `dark` を付けている。
  - 同じリポジトリに `/`（EDINET分析）・`/tasks`・`/midterm`・`/analyze` があり、これらは端末の設定に従わせたい。だから `dark:` を丸ごとクラス基準に**置き換える**のではなく、条件を**足す**。置き換えると他のページが二度とダークにならない。
  - `color-scheme: dark` も `.dark` に付ける。付けないとチェックボックスや入力欄など、ブラウザが描く部品だけライトのまま残る。

  - `theme-color` はルートで端末設定に振り分けているため、`app/english/page.tsx` 側で `export const viewport` を出して黒に固定する（Next.js のページ単位の `viewport` はルートの指定を上書きする）。

  - あわせて viewport に `interactiveWidget: "resizes-content"` を指定。キーボードが出たぶん svh が縮んでレイアウトごと収まり、ページが押し上げられない。
- カードの地色は場面で塗り分ける。**4択を開いているあいだは黄**（まだ正誤が決まっていないので △ と同じ色）、**回答後は正解 (○ / △→正解) が青、不正解 (× / △→誤答) が赤**。`CARD_TONE` が地色・枠線・影の3つをまとめて持つ（`cardTone()` に rgb を渡して生成）。
  - **青だけ地色の濃さを 2.6倍にしてある**（`cardTone()` の第2引数 `fill`）。`#4A99EA` は黄や赤より明度が高く、同じ不透明度だと白地に沈んで「色が付いていない」ように見える（実際に「青のみ薄すぎて何も見えない」と報告された）。倍率は地色のグラデーションにだけ掛け、枠線と影には掛けない。掛けると青だけ枠が不透明になって、3色で輪郭の強さが揃わなくなる。
  - 色は塗り替えではなく `backgroundImage` で**白地の上に重ねる**。`bg-white` を残したまま乗せられるので、文字の読みやすさが落ちない。

  - 解説の枠と4択のボタンは `bg-zinc-100` ではなく `bg-white/70〜75`。地色の上にグレーを置くと色が濁る。
  - スワイプ中は正誤の影ではなくスワイプの影を優先する。両方出すと指の向きが分からなくなる。
  - 判定は「塗りつぶしバッジ (○ / ×) ＋ 正解 / 不正解」の1行。以前は `ACTION_LABEL` の記号をそのまま出していたが、バッジと並ぶと「○ ○」と重複した。△ で答えたときだけ「△ で回答 ・ 選択: ◯◯」を小さく添える。

- 次に出るカードは、今のカードの後ろに中身ごと重ねておく（`NextCard`）。今のカードを横へずらすと次の単語がのぞく。
  - 静止時は `scale(0.95) translateY(18px)`、今のカードを引っぱった強さ `t` に比例して等倍・定位置へせり上がる。`t=1` で手前のカードと完全に重なるので、カードが飛んでいって次の単語に差し替わる瞬間に位置が飛ばない。
  - めくっているあいだ（`flip`）は背面のカードを消す。手前のカードが `scaleX(0.02)` まで細くなるので、消さないと回答した直後に次の単語が読めてしまう。
  - キューは使い切ってから作り直すのではなく、**残り1枚になった時点で継ぎ足す**。使い切ってから補充する方式だと、バッチの最後の1枚だけ背面に重ねるカードが無くなる。継ぎ足しのたびに直近正解率によるレベル自動調整（`evaluateLevelShift`）を判定するのは以前と同じ。キューが伸び続けないよう3バッチぶんを超えたら先頭を捨て、`index` をその分ずらす。

- 逆にカード詳細シートは常に黒地・白文字で固定。白いカードから開いたときに反転するのを見せ場にしているので、テーマで変えない。
- カードの動きは transition ではなく **CSS アニメーション**で作る（`app/globals.css`）。transition は1回のオーバーシュートしか作れず、跳ね返りや回転が単調になるため。
  - アニメーションは通常のインラインスタイルより優先されるので、`style={{ transform }}` を上書きできる。ただし **transition はアニメーションよりさらに優先される**ので、アニメーションを効かせる場面では `transition: "none"` にする（飛んでいくあいだがこれ）。
  - 開始位置は CSS 変数で渡す（`--bounce-from` / `--fly-x` `--fly-y` `--fly-r`）。0 から始めると、指を離した位置からいったん中央へ戻ってから動いて見える。
- 4択を開くときだけはカードを裏返さない。上へ引っぱったカードは指を離した高さから**減衰しながら数回揺れて**元の位置へ戻る（`card-bounce-back`、0.82s）。キーフレーム間の緩急は既定の `ease` に任せる（`linear` にすると機械的に見える）。
  - 単語・品詞と4択の登場（`choices-rise` / `choices-rise-late`）は **0.18〜0.2s で終わらせる**。カードの跳ね返りは子要素にもそのまま効くので、中身は素早く定位置に着けてしまい、あとはカードの動きに乗せる。ここを長くすると中身だけ別の動きをして、跳ねているカードから浮いて見える（実測で 0.24s には中身の自前の移動が 0 になり、以後はカードの揺れだけが残る）。
  - 裏返しの演出（`flipTo`）は回答後の解説へ移るときだけに残してある。4択は「まだ答えていない」場面なので、めくると回答したように見える。
- 回答したカードは、指ではじいた向きへ**1回転半しながら縮んで飛んでいく**（`card-fly-right` / `card-fly-left` / `card-fly-up`、0.6s、`cubic-bezier(0.36, 0.11, 0.4, 1)`）。大きな記号（○ / ×）も付けたまま一緒に飛ばす。
  - 回転は 540度まで。2回転（720度）を 0.45s で回すと残像になり、回っていること自体が見えなかった。
  - 縮みも 0.45 止まりにしてカードの面を読めるようにする。
  - `opacity` は **画面の外へ抜ける直前（42%→48%）だけ**落とす。序盤から薄くすると下のカードが透けて、紙が重なって見えなくなる。
    - なぜ必要か: カードは不透明な白なので、画面端に差しかかった瞬間の辺がそのまま残る。しかも**抜ける頃にちょうど回転が180°付近**になるため辺が垂直になり、画面端に白い直線として1〜2フレーム見える（実測: 描画右端21pxのとき回転-174°）。「たまに見える」と報告された現象の正体はこれ。
    - **消す時刻は必ず実測して合わせる。** 抜け切る割合は距離とイージングだけで決まり、時間を変えても 48% のまま動かない（375px幅の実測: 0.9s なら 429ms、1.1s なら 523ms）。だから時間を変えたときに 42%/48% を直す必要はない。逆にイージングか `translate` の 150% を変えたら、必ず測り直して合わせること。
  - **「速すぎる」と言われた原因は速度ではなく、消すのが早すぎたこと。** 以前は 0.75s で 15%→21% に落としており、opacity が 0 になる 161ms の時点でカードの左端はまだ x=29、つまり画面のほぼ全面を覆っていた。飛んでいくところが見えないまま画面の真ん中で消えていた。今（0.9s）は全面が見えているのが 387ms まで、消え切るのが 437ms で、161ms から約2.7倍になっている。
  - 長さの変遷: 0.75s（消えるのが早すぎて「速すぎる」と誤認される）→ 1.1s → 0.9s → **0.6s（ユーザーの指定。体感1.5倍）**。抜け切る割合はイージングと距離だけで決まり時間に依存しないので、時間を変えても opacity の 42%/48% は動かさなくてよい。0.6s では全面が見えるのが約260ms・消え切りが約290ms。`EXIT_MS`（600）と必ず揃える。
  - 時間を延ばすだけでは体感は変わらない（前に 0.45s→0.75s に延ばしたが変わらなかった）。曲線が前寄りだと延ばしたぶんは画面外で回るだけになる。見えている時間を延ばすには**第1制御点の y を下げて序盤の移動そのものを遅くする**。出だしを速くしすぎる曲線（`cubic-bezier(0.24, 0.6, ...)`）は序盤で回りきって残りが間延びする。
- **飛んでいくカードは「触れない見た目だけのコピー」**。飛ばすと決まった瞬間に `onFly()` で今の見た目（単語・面・回答・指を離した位置）を親へ渡し、本体は待たずに次の単語へ差し替える。
  - コピーは `flyingLayer` として本体に重ねる。`WordCard` に `ghost` を渡した姿で、根に `pointer-events-none`、ボタン列は `invisible`（レイアウトの高さを本体と揃えるため、消さずに透明にする）。詳細シートも開けない。

  - **背面カードの枠（`nextItem` が無いときのプレースホルダー）はコピーには描かない。** コピーは本体に重ねてあるので、中身のない枠線だけが下のカードの上に浮いて見える。
  - こうしないと、飛んでいるあいだ下のカードもボタンも触れない。実測でも、飛行中にカード中央をヒットテストすると必ず本体側に当たる。
  - コピーは飛んだ瞬間の面をそのまま見せるため、`initialStep` / `initialAction` / `initialPicked` / `initialChoices` を渡してマウントする。面ごとの描き分けを別実装にすると本体とずれるので、同じ `WordCard` を使い回す。
  - 振動（`navigator.vibrate`）はコピー側では鳴らさない。本体で既に鳴らしているので二重になる。
  - **コピーは配列で持つ（同時に何枚でも飛ばせる）。** `EXIT_MS + 80` の後に自分の `key` のぶんだけ配列から取り除く。1枚しか持たない作りにすると、前のカードが飛びきる前に次を飛ばした時点で差し替わり、飛んでいる途中でふっと消える。演習モードは続けて仕分ける前提なので、飛行時間しだいで起きやすさが変わる (0.6s でも速い連打では起きる)。
- カードを飛ばした直後、ボタン列はスワイプ中の縮んだ状態から跳ねて戻る（`buttons-settle`、0.26s）。次のカードをすぐ叩けるよう短く収束させる。`transform` だけなのでアニメーション中もタップは通る。
  - このクラスは**マウント時の値で固定する**（`useState(settleButtons)`）。prop をそのまま見ると、親が飛行中のコピーを片付けた時点でクラスが外れ、跳ねが途中で切れる。
  - 飛ぶ時間は `VocabTab` の `EXIT_MS` と `globals.css` の `card-fly-*` で**必ず揃える**。`EXIT_MS` のほうが短いと、飛びきる前に次のカードへ差し替わってアニメーションが途中で切れる。
  - 飛んでいるあいだ、背面のカードはすでに等倍・定位置まで上がっている。次の単語は先に読めているので、0.22s から 0.45s へ伸ばしても待たされた感じにはならない。
- 詳細を開く演出は3つが同時に動く。カード画面側で ↑ボタン・カード・下部ボタン列の矩形を測って `SheetOrigin` として渡し、シート側で差分を出している。閉じるボタンと回答バーはパネルの拡大に巻き込まれないよう、`transform` を持つパネルの外に置く。
  - パネル: カードの矩形（位置と幅の比）から等倍へ広がり、画面全体を覆う。
  - 閉じるボタン: ↑ の位置から `rotate(-180deg)` で始まり、回りながら右上へ移動して ↓ になる。
  - 回答バー: カード画面のボタン列の位置から画面下端へ下りる。ボタンの間隔はカード画面と揃える（どちらも `gap-3`、× ○ が h-16、? が h-14）。ここがずれると閉じるときの着地点が実際のボタンと食い違い、動きが不連続に見える。
- ↓ で閉じるときは同じ3つを逆向きに動かしてから `onClose()` を呼ぶ（`phase` は `start` / `open` / `closing` / `dismissing` の4状態）。開始位置へ「飛ばす」ときは `transition: none`、「戻す」ときだけアニメーションさせる点に注意。
- **カード詳細は下へ引いても閉じる**（`dismissing`）。↓ ボタンの逆再生とは別で、引いた指の延長でそのまま下へ抜ける。カード画面から開いても単語リストから開いても同じ。
  - 引き始めた時点で中身が先頭（`scrollTop === 0`）のときだけ効かせる。途中から効かせると、本文を読み進めようとした指で閉じてしまう（`Sheet.tsx` の閉じるスワイプと同じ考え方）。
  - **タッチの追跡はネイティブの touch イベントで行い、pointer イベントに頼らない**（`beginDrag` / `moveDrag` / `finishDrag` を touch とマウス pointer の両方から呼ぶ）。理由は2つ。
    1. pointer イベントはブラウザがジェスチャをスクロールと判定した瞬間 `pointercancel` で途切れる。その判定のスロップ（8〜10px）はこちらの発動しきい値（14px）より小さいので、**pointer 追跡は競争に必ず負ける**。最初の実装（pointer のみ）はこれで実機で全く効かなかった。`touchmove` はスクロールが始まっても配送され続ける。
    2. `preventDefault` は React の `onTouchMove` では効かない（React はルートに passive で付ける）。`ref` + `addEventListener({ passive: false })` が必須。
  - `preventDefault` は「先頭から下向きに動いている」あいだずっと呼ぶ。先頭にいる以上、下向きの引きで動かせるスクロールは存在しないので正当なスクロールを殺すことはない。上向き（dy < 0）は止めず、ふつうのスクロールに返す。
  - ハンドラはスクロールしない根の要素に置く（`Sheet.tsx` と同じ構造）。ネイティブリスナーはマウント時のクロージャに古い state が残るので、`phase` とドラッグ関数は ref 越しに読む。
  - 確定はカードのスワイプと同じく距離と速さの両方で見る（110px、または 24px 以上動いていて 0.5px/ms 超）。
  - **引く操作とみなす最小移動量（`DISMISS_SLOP`）は、ブラウザが「タップ」とみなす移動量より必ず大きくする（14px）。** iOS Safari は約10pt、Android Chrome は約8dp 動いても click を出す。ここを 6px にしていたときは、下へ8pxぶれたふつうのタップでも引く操作と判定され、直後の click を握りつぶして**詳細内の編集ボタンやチップが1回効かなくなった**（ついでにタップのたびにパネルが数px沈んで戻った）。
  - **閉じるボタンと回答バーはパネルの外にある**ので、`dismissStyle` を3つとも同じだけ効かせる。パネルだけ下げると2つが宙に取り残される。
  - 引いて離した指の下のボタンが誤爆しないよう、`onClickCapture` で直後のクリックを1回だけ握りつぶす。**目印は次の `onPointerDown` で必ず下ろす。** 指を大きく動かすとブラウザが click を出さないことがあり、下ろさないと目印が残って次のふつうのタップを食う。
- **カード詳細の下部バーから回答したら、「解説を飛ばす」設定に関わらず裏面を見せずに飛ばす**（`answer(a, fromDetail)`）。詳細で意味も例文も読んだ直後なので、もう一度解説を出す意味がない。
  - 飛ばすコピーの面は `flyAway` の第3引数で明示的に `"ask"` にする。裏返していないので表を描かせる。
  - 復習で △ を押したときは4択を出さない（意味がもう見えているので出す意味がない）。`unsure_wrong`（△→×）として数える。
- 閉じるイージングは開くときと同じ `cubic-bezier(0.22, 1, 0.36, 1)`。数式どおり反転した `cubic-bezier(0.64, 0, 0.78, 0)` も、立ち上がりを早めた `cubic-bezier(0.35, 0.12, 0.7, 0.45)` も出だしが鈍く感じるため却下した。閉じる操作は「ゆっくり離れて加速」より「押した瞬間に飛ぶ」ほうが速く感じる。
- 閉じるボタンは開くときも閉じるときも、移動しながら180度回る（開: `rotate(-180deg)` → 0 で ↑ が ↓ になる。閉: 0 → `rotate(-180deg)`）。`flyStyle` の第2引数が回転量。
- カード画面に「n語回答 / n正解」のセッション集計は出さない。集計用の state ごと削除済みで、復活させるなら再度持たせる必要がある。
- `SWIPE_HINT` の `max` はフォントサイズの上限。どれも1文字なので大きく出せる（英字だった頃は "Mastered" が8文字あり、カード幅からはみ出さないよう小さく抑えていた）。
- AI会話の「メッセージ添削」は、AIの返信とは別の `role: "correction"` として履歴に入れ、必ず返信より前に置く。見た目も吹き出しではなく幅いっぱいの破線枠にして、会話の相手ではなく注釈だと分かるようにしてある。
- 添削と返信は1回のAPI呼び出しでまとめて作る（2回に分けるとレイテンシが倍になり、返信が添削の内容に引きずられる）。
- 添削をオンにしているあいだは `correction` を必ず埋めさせる。プロンプトで3つに書き分ける。(a) 誤りがあれば直した英文＋日本語の説明、(b) 直すところが無ければ「直すところはありません。」＋もう一段自然な言い換え、(c) 日本語で書かれたらその英訳＋補足。
  - 以前は (b) と (c) を空文字にさせていたが、日本語話者の学習者は日本語か素直な英語を書くことが多く、結果としてチェックを入れても添削がほぼ出ないという不具合になった（実際にそう報告された）。空なら描画しない側の処理は保険として残してある。
  - (c) を添削側に持たせたので、返信側の「日本語で書かれたら英訳を示す」ルールは添削オンのときだけ外す。両方でやると同じ英訳が2回出る。
- APIへ送る履歴からは添削を除く。添削は直前のユーザー発言に対するもので、会話の流れには属さないため。
- 会話のAIレベルは自動設定だと単語学習の測定値（`vocabLevel.current`）に追随する。文法の難易度が `settings.level` 側なのと出どころが違うので注意。
- 設定と各タブのフィルタは画面遷移ではなくポップアップ。`Sheet` はマウントしたままにして `open` の切り替えだけで出し入れする（出し入れのたびに作り直すと、開くアニメーションのために1フレーム待つ必要が出る）。上端はヘッダーの高さぶん下げた枠を `overflow-hidden` にして、その中でパネルを `translateY(-101%)` から 0 へ動かす。こうするとヘッダーの裏から出てくるように見える。
- `Sheet` の閉じるスワイプは、中身がスクロールできる場所から引き始めたときは無効にする（スクロールと取り合いになるため）。引く向きの端まで来ているときと、つまみからの操作だけ閉じる動きにする。上のシートは下端、下のシートは上端が判定の基準。
- `Sheet` の背面は全画面 (`fixed inset-0 z-[45]`) にして、ポップアップ以外のどこを触っても閉じるようにする。ボトムナビ (z-40) や呼び出したボタンより手前に置くので、開いている間はそれらへのタップも「閉じる」になる（呼び出したボタンを押したときと同じ結果なので、トグルの挙動は保たれる）。ポップアップ本体は z-50。
- 座標は呼び出し側から px で渡す。上のシートはヘッダー61から、下のシートは上タブの下端122+16=138から。これらの高さを変えたら `Sheet` の引数も直す。
- 下タブのラベルは選択中だけ太字にするが、太字ぶんの幅を不可視のコピーで常に確保しておく（`grid` で重ねる）。確保しないと「カード」と「AI会話」だけ選択の瞬間に幅が変わってタブがずれる。日本語2文字のラベルは太字でも幅が変わらないので気づきにくい。
- レイアウトはアプリシェル。ページ（document）は縦にも横にも一切スクロールさせず、`page.tsx` の `main` を `h-svh` で画面ぴったりに固定し、EnglishApp 内の「唯一のスクロールコンテナ」（`overflow-x-hidden overflow-y-auto` のラッパー）だけをスクロールさせる。ボトムナビは `fixed` ではなくシェルの最下段の通常フロー。
  - こうしている理由: ページがスクロール可能かどうかがタブごとに変わると、ビューポートの高さが再計算されて `fixed` のナビが数百ミリ秒だけ下にずれて戻る（実測でナビ 752→769.5→752px、実機ではURLバーの開閉も走る）。document を常に画面ぴったりにすれば引き金ごと消える。
  - 横スクロールする枠 (`overflow-x-auto`) には必ず `overflow-y-hidden` を添える。`overflow-x` だけ auto にすると `overflow-y` も auto に格上げされ、縦に伸びない枠が縦スワイプを飲み込んで外側のスクロールに渡らなくなる（単語リストの表と、カード画面の上部タブがこれで一度スクロール不能になった）。
  - タブ切り替えの横スライド演出（`translateX(24px)`）は中身を右へ8pxはみ出させる。スクロールコンテナの `overflow-x-hidden` がこれを遮断する。外すとページが横に383pxへ広がり、上のずれが再発する。
  - カード画面と AI会話 のルートは `h-full`（スクロールコンテナの高さいっぱい）。以前の `100svh-173px` のような画面高からの逆算はもう使わない。
  - body は `min-h-svh`。`min-h-screen`（=100vh）だとモバイルでURLバーのぶん必ず縦スクロールが生まれる。
- 文法・読解の生成条件は「生成条件」の1トグルにまとめ、その中に個別の条件を入れ子で並べる。教材より上に設定が積み上がって画面を圧迫するのを防ぐため。閉じたままでも今の条件が要約行で分かるようにする。
- 読解の長文リストは直近5件だけ出し、残りは「さらに表示」で開く（`READING_LIST_LIMIT`）。
- スワイプの確定は**距離と速さの両方**で見る（`committed()`）。`SWIPE_THRESHOLD`(60px) を超えるか、`FLICK_MIN_PX`(22px) 以上動いていて速さが `FLICK_SPEED`(0.4px/ms) を超えれば確定する。距離だけで見ると毎回大きく指を動かすことになる。
  - 速さは直近120msの軌跡（`histRef`）から出す。窓を広く取ると、動かしてから止めて離しても「速い」と判定されてしまう。
  - どの向きに確定するかは、演出（`swipe`）と同じ「大きく動いた軸」で決める。別々の基準にすると、見えている向きと違う回答が確定する。
  - 実測: 40px をゆっくり=確定しない / 30px を素早く=確定する / 75px をゆっくり=確定する / 15px を素早く=確定しない。

- AI会話の履歴削除はタブのゴミ箱ではなく、入力欄の上の「会話をリセット」ボタン。履歴が空のときも表示したまま無効化する（出し入れすると入力欄の位置がずれるため）。

- カード詳細のステータスは手で付け替えられる。`VocabEntry.statusOverride` に持たせ、`wordStatus()` が学習記録より優先して返す。エントリに持たせているので、`buildQueue`・`dbStats`・単語一覧・タブの件数すべてに自動で効く（引数を増やして各所へ配る必要がない）。

  - 未学習の語に指定するときは空のエントリを作り、「自動」に戻したときそのエントリが未回答のままなら丸ごと消す。
- ステータスの表示名と配色は `worddb.ts` の `STATUS_BADGE` が唯一の定義。以前ここが単語一覧側に二重定義されていて「既知」と「学習済み」が食い違ったので、増やすときも1箇所に置く。

- 本文のハイライト語は押すと `CardDetailSheet`（一覧・カードと同じモジュール）が長文の上に重なって開く。編集・メモ・ステータスの保存先も共通（`edits` / `notes` / `vocab`）。
  - 本文中の表記から単語DBを引くとき、大文字と代表的な活用（-s/-es/-ies/-ed/-ing）だけ剥がして照合する。完全な語形還元はしない。
  - DBに無い語（旧DB由来の学習記録など）は、`data.vocab` の意味から簡易エントリを合成して開く。例文などは空になるが、押して何も起きないよりよい。
- 長文に織り込む単語は前回結果が × と △ のものから採る（以前は `needsReview` だけ）。ターゲットが主役になるよう題材を先に決めさせるプロンプトにしてある。
- 取り消せない操作の確認に `window.confirm` を使わない。ホーム画面から起動した場合など、環境によっては**何も表示せず false を返す**（この不具合で「会話をリセット」が無反応だった）。代わりに `ConfirmButton` で、1回目のタップで「本当に？」に変わり2回目で実行する二段階にする。6秒放置で元に戻る。
- ルートの `<html>` に高さを固定しない。`h-full` を付けると本文がはみ出しても html 側が伸びず、スマホで縦スクロールできなくなる。
- `lastCorrectAt` は廃止済み。鮮度は `lastSeenAt` で見る。
- 学習履歴の数値リング（`statsRowRetired`）は VocabTab に未使用のまま残してある。再実装する可能性があるため消していない。

- 上部タブを**演習 / 復習の2モード**に作り替えた。演習は × ○ の2ボタンで裏面を見せず高速に仕分ける、
  復習は × △ ○ の3ボタンで解説を見せる。更新（↺）とコメント（💬）のボタンは削除。
- 演習の出題は新出 : 既出を `drillNewRatio`（既定50%）で混ぜる。設定シートから変更できる。
- レベルの自動調整は演習モードの回答だけで判定する。

ステータス
- **2軸に分離**した。前回結果（○ / △ / ×）と学習進捗度（未学習 / 学習中 / 学習完了）。
  出題対象は学習進捗度で決める（復習＝学習中）。
- 学習完了は「初見で○」または「○が3回連続」かつ**前回結果が○**。差し戻しの条件が無いと、
  一度完了した語が忘れても永久に完了のままで復習に出てこなくなる（実データで12語が該当していた）。
- `?` の表記を全部 `△` にして黄色に統一。回答の3種はすべて記号（○ / △ / ×）。

単語リスト
- 列を 単語 / 意味 / 学習進捗度 / 前回結果 / ○ / △ / × / 最終閲覧 に。並びは `COLUMN_ORDER`。
- 既定の並べ替えは「前回結果 昇順 → 学習進捗度 昇順 → 単語 昇順」の3段。
- 単語・意味の見出しに**シールボタン**。列を隠して1つずつめくれる（アニメーションは付けない）。

見た目・操作
- スワイプの確定を距離だけでなく**速さでも**見るようにした（軽く弾くだけで確定する）。
- 飛んでいくカードを**触れないコピー**にして、飛行中でも次のカードを操作できるようにした。
- 4択を開くときはカードを裏返さず、跳ね返りで戻す。
- 裏面と4択でカードの地色を塗り分ける（黄 / 青 / 赤）。
- カード詳細の並びを 意味 → 例文 → 派生語・関連語 → メモ → タグ → ステータス → 背景画像 に。

データ
- 単語DB（B1）に、生成時のAIの文字化けで見出し語が壊れたエントリが2件あったので直した。
  - `客 service` → `customer service`。発音記号 `/ˈkʌstəmər ˈsɜːrvɪs/` と `related` が
    元の語を示していた。例文が `service` の話になっていたので見出し語を使う文に差し替え、
    `related` から見出し語自身への参照を外した。
  - `союз`（本来は `union`）は**削除した**。綴りを直すと B2 の `union`（意味「労働組合」、
    同じ発音記号）と重複するため。DBは全レベル通しで重複ゼロを保っており、
    ここだけ唯一の重複を作りたくない。B2 側のほうが `related` も `exams` も充実している。
  - B1 の `count` を 1262 → 1261 に更新。語彙は 6,020 → 6,019 語。
  - 見出し語の非ASCII混入と重複はこの2件だけ（全レベル・語彙とイディオムを走査して確認）。
  - 消した語に学習記録が残っている端末では `data.vocab["союз"]` が孤児として残るが、
    単語リストの行はDBから作るので画面には出ない。

### 検証のやり方（このセッションで有効だった手順）

- 画面の確認は必ずモバイル幅（375×812）。`resize_window` の `colorScheme` を light にして、
  端末がライトモードでもダークのままかを見る。
- **そもそも学習記録に触らずに済ませる。** カードやボタンを叩かなくても、
  `body` に検証用の要素を挿してクラスやスタイルを当てれば、アニメーションも配色も測れる。
  飛行の計測は 343×600 の `div` に `card-fly-right` を当てて `DOMMatrixReadOnly` で四隅を出した。
  カードの地色は「白地 + `backgroundImage` の重ね」という実物と同じ組み立てで並べて撮り比べた。
- どうしても回答が要るときだけ localStorage を退避し、終わったら必ず戻す。
  ただし**ブラウザペインはユーザーも触れる**。退避してから戻すまでのあいだにユーザーが
  カードに答えていると、戻した瞬間にその操作を巻き戻してしまう。
  戻す前に退避時点との差分を必ず確認すること（実際に、退避後に5件の回答が増えていた）。
- **ジェスチャ（ドラッグ・スワイプ）の検証は合成イベントでは不十分。** `dispatchEvent` で作った
  PointerEvent はブラウザのジェスチャ認識（スクロール判定 → pointercancel）を通らないので、
  「合成では動くのに実機で全く効かない」を実際にやった。`computer` の `left_click_drag`
  （モバイルプリセットはマウスをタッチに変換する）で**実入力**を通すこと。
  ツールが30秒でタイムアウト表示になっても入力自体は届いていることがあるので、
  結果は画面の状態で判定する。
- アニメーションの検証は目視ではなく計測で行う。`getComputedStyle` を数十msごとに読む、
  `DOMMatrixReadOnly` で四隅を出す、`animationPlayState='paused'` で止めて撮る、など。
  **ブラウザペインが非表示だと rAF とCSSアニメーションが止まる**ので、
  計測前にスクリーンショットを撮ってペインを表示させておくこと（これで一度、
  ゴーストが早期に消えたように見える誤計測をした）。
- 借りている開発サーバーは `app/globals.css` の再ビルドが数分遅れることがある。
  CSSを触ったら**配信中のCSSを直接見る**か、`npx next build` の出力を確認する。
  最小化で `0.75s` が `.75s` になる点に注意（grep が外れる）。
  - **開発サーバーが動いているあいだに `git stash` しない。** サーバーが stash 中の
    HEAD 版を掴んだまま戻ってこなくなる（`touch` しても再ビルドされなかった）。
    eslint の基準値を取りたいだけなら、stash ではなく `git show HEAD:path` を使う。
  - CSS が配信に反映されないときは、同じ内容の `<style>` をページに挿して測ればよい。
    測っているのは自分が書いたCSSそのものなので、ビルド経路の遅れとは切り分けられる。
    そのうえで `npx next build` の成果物を grep して、本番の値が合っているかを別途確かめる。
- eslint の基準値はリポジトリで違う。claudecode 側は10件（`components/tasks/TaskApp.tsx` を含む）、
  デプロイ用リポジトリ側は9件。件数だけを見て「増えていないか」で判断する。
- 単語DBを触ったら、全レベルを走査して「見出し語の非ASCII混入ゼロ」「重複ゼロ」
  「`count` と `words.length` の一致」を確認する。JSONは `JSON.stringify(j, null, 1)` で
  バイト単位の往復が取れるので、スクリプトで書き換えても差分は変更箇所だけになる。
- 出題キューや復習間隔のような**純粋なロジックは画面を触らずに検算する**。
  `scripts/check-english-schedule.ts` のように単体でコンパイルして走らせればよい
  （テスト基盤は無い。コマンドはそのファイルの冒頭にある）。
  合成データで「タブの件数」と「`buildQueue` が実際に拾う語の集合」を突き合わせられるので、
  画面を操作して学習記録を汚す必要がない。
- **ブラウザのAPIに頼る機能は、必ず実際の端末で値を出して確かめる。**
  読み上げの音声選びはこれで不具合が見つかった（`getVoices()` の中身を数えたら、
  en-US に `default` が1つも無く、先頭がジョーク音声だった）。
  「たぶんこう動く」で済ませず、`getVoices()` の一覧のように**実際の値を出力して見る**こと。
